# 2026-09-06 — rule.md realigned to the Charter, and the gaps it exposed

**Course:** 1305493 · W5 · **Owner:** Thiha Lin, Tech Lead
**Closes:** B12, B26–B31 · **Leaves open:** B16, B17 (both evidence, neither code)

---

## What was wrong

A conformance pass over `rule.md` against the repo found that the two disagreed about what
the product *is*. The W2 workshop brief opens:

> **1. Pick YOUR product — the one in your Company Charter, not a case company.**

The draft written in class did not. It analysed a generic upload-and-edit service — *"we
receive and host other people's files"*, funded by *"advertising through Google AdSense"* —
and concluded the Computer Crime Act §26 access log was mandatory for us.

The Charter's product has no upload path, no ads, and no accounts. So the draft's own LR1
and LR2 required a server that does not exist, and building one would have contradicted its
**own PDPA rule 13** ("if a transformation can run in the browser, run it in the browser and
never upload") in the same file.

## What changed

`rule.md` was rewritten against the Charter's product, keeping the W2 shape exactly: three
laws, *what it is / what it requires / rules for the agent*, direct commands to the AI. The
class draft is preserved verbatim at `01-requirements/04-legal/rule-as-submitted-20260819.md`
— the graded submission survives the rewrite.

Two decisions worth recording:

- **Nothing was deleted.** Every duty the draft identified is still present, either as a live
  rule or in a **"Duties this architecture removes"** table that states the duty, why it does
  not bind, and the rule that keeps it that way. §26 is now written conditionally — *"if the
  system ever stores a file for a user, this duty returns in full"* — so the reasoning
  survives for whoever reads it next term.
- **Logging nothing is the compliant state**, and that had to be made explicit. An access log
  of IP addresses, added out of caution, would itself be a PDPA collection with no lawful
  basis. CCA rule 8 now says so, so the absence stays a decision rather than an oversight.

## The five gaps the conformance pass found

Reading the rules against the code turned up real defects, not paperwork:

| Rule | Defect | Fix |
|---|---|---|
| PDPA 8 | `<input accept>` filters only the OS picker — **a dragged file bypassed it entirely**, so a 4 GB ISO could reach an image decoder | `src/intake.js` screens both paths; 8 tests |
| PDPA 7 | `compress-image` could return the original file untouched when compression would not help — **GPS coordinates intact** | `preserveExif:false` stated, plus a re-encode guard |
| PDPA 11 | Retention was only a countdown, met *after* committing a file | Stated as a number on the uploader |
| PDPA 24 | The deletion promise had **no test at all** | `test/vault-deletion.test.mjs` — resolves the object URL to prove the bytes are unreachable, since PDPA 13 says a flag is not deletion |
| PDPA 6 | `console.error(err)` shipped, and error messages name the file — *"Could not read holiday-photo.jpg"* — so **a filename reached the production console** | `src/log.js`; absence verified in the built bundle |

`rule.md` PDPA 25 also required a privacy page, which did not exist. `src/privacy.js` now
answers the six questions the rule lists, and reads the retention window and size limit from
the code so the page cannot drift from what is enforced.

## Where the gate stands

**B12 is closed.** Two blockers remain — **B16** (0 of ≥5 interviews) and **B17** (topic
approval unconfirmed). Neither is code, and neither is closed by building anything. The
product remains far ahead of its evidence, which is still the project's central risk.

# 2026-09-06 (later) — W3 bridge: W1 → W2 → W3 made explicit

**Closes:** the W3 workshop items that were still implicit · **Leaves open:** B16, B17

## Why anything was left to do

W3's deliverables — the spec, the backlog, `requirement-writer`, `audit-backlog` — already
existed. What did not exist was the **bridge**: nothing in the repo stated, in one place, that
the Charter decides the product, `rule.md` applies the law *to that product*, and the spec's
LR items are `rule.md`'s Must rules renumbered. A grader could verify each document alone and
still not see the chain the W5 gate actually grades.

## What was added

- **`.docs/01-requirements/TRACEABILITY.md`** — the chain on one screen: which week decides
  what, W1 → W2 (why `rule.md` reaches the conclusions it does), W2 → W3 (each LR and the
  `rule.md` rules behind it), and W3's `pain → requirement → backlog` table for all 14
  functional requirements.
- **`.claude/skills/capture-requirement/`** — the missing skill from the W3 target tree, and
  the only sanctioned route from `H#` to `P#`. Promotion needs **two** participants describing
  a pain unprompted; one is an anecdote. It refuses to invent a pain or a participant.

## What the audit found

`/audit-backlog`'s four checks, run against 31 backlog rows and 16 Must requirements:

| Check | Result |
|---|---|
| Coverage — every Must has a backlog row | **pass** |
| Provenance — every row cites an id that exists | **pass** |
| Priority agreement | **pass** |
| Legal coverage — every Must rule in `rule.md` has an LR | **pass**, LR1–LR7 |

Writing `TRACEABILITY.md` did surface two **wrong claims in the draft of that file itself**:
it credited B19 to F11 (it is F10, merge PDFs) and B10 to F12 (it is F14, language coverage).
Both were corrected against `backlog.md` before commit, and a check now verifies every F→B
mapping in the file against the backlog rather than trusting it.

## What is deliberately still open

**0 of ≥5 interviews (B16).** All 14 functional requirements still trace to an `H#`. The
tooling to fix that is now in place and mechanical; the interviews are not, and no amount of
building substitutes for them. **B17** (topic approval) is likewise unchanged.
