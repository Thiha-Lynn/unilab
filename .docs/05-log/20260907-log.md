## What changed, and why each one is a real finding rather than tidying

**B10 — closed (a genuine product defect).** `registry.js:149` advertised OCR as *"English and
Thai"*; `README.md:47` said *"Thai + Burmese"*; `ocr-pdf.js` ships `tha` + `eng` + `mya`. Three
descriptions, none matching, and the one group most likely to need Burmese OCR — a large part of
the MFU student body — could not see it was supported. Both strings now read **Thai, English and
Burmese**. `npm run build` clean.

**B14 — closed by verification, not by building.** The row asked whether Remove Background
discloses its model download the way OCR does. It does: `remove-background.js` `modelGate()`
downloads **zero bytes** on open and puts the model behind a button that names the size. So
**NFR5 is now 2 of 2 tools disclosing**, and **LR3** moves from *"partially satisfied"* to
satisfied and verified. Nothing was written to close this row — the code was already right and
the backlog was stale about it.

**LR8 — new, and the most substantive find.** `rule.md` PDPA rule 6 (no filename, file content
or object URL in a production console) is Must-level. It was enforced in code (`src/log.js`) and
had a backlog row (B30), but it **never became an LR**, so B30 cited a raw rule instead of a
requirement id. That is exactly the break check 4 exists to catch. LR8 is now in `rule.md`'s
carry table, spec §4 and `TRACEABILITY.md`.

**D6 / B24 — a miscitation that would have read as carelessness.** B24 ("draw the desktop
two-pane work stage") cited **D3**, which is the `rule.md` defect — an unrelated row. The real
evidence was sitting in `prototype.md`'s own "Known gaps". That gap is now **D6** in the spec's
defect table, B24 cites it, and B24 was raised to **Must** to agree with F5 — a gate reviewer
opens the prototype on a desktop, so shipping only the 480 px layout is not a *Should*.

**B34 — new.** NFR4 ("interactive < 2 s") is the one NFR with no agreed measurement basis and no
backlog row. Until a reference device is named in the repo (Q3), the threshold is untestable and
must not be claimed at the gate.

**B22 / B23 / B25 — moved, not renumbered.** These three are gate *process* rows, not product
requirements, and no honest requirement id exists for them. Inventing one to satisfy check 2
would have been the wrong fix. They now sit in their own **Gate deliverables** table citing the
rubric, so the product backlog holds one invariant cleanly: every product row traces to a
requirement id.
