## What changed, and why each one is a real finding rather than tidying

**B10 — closed (a genuine product defect).** `registry.js:149` advertised OCR as *"English and
Thai"*; `README.md:47` said *"Thai + Burmese"*; `ocr-pdf.js` ships `tha` + `eng` + `mya`. Three
descriptions, none matching, and the one group most likely to need Burmese OCR — a large part of
the MFU student body — could not see it was supported. Both strings now read **Thai, English and
Burmese**. `npm run build` clean.

**B14 — closed by verification, not by building.** The row asked whether Remove Background
discloses its model download the way OCR does. It does: `remove-background.js` `modelGate()`
downloads **zero bytes** on open and puts the model behind a button that names the size. So
**NFR5 is now 2 of 2 tools disclosing**, and **LR3** moves from *"partially satisfied"* to
satisfied and verified. Nothing was written to close this row — the code was already right and
the backlog was stale about it.

**LR8 — new, and the most substantive find.** `rule.md` PDPA rule 6 (no filename, file content
or object URL in a production console) is Must-level. It was enforced in code (`src/log.js`) and
had a backlog row (B30), but it **never became an LR**, so B30 cited a raw rule instead of a
requirement id. That is exactly the break check 4 exists to catch. LR8 is now in `rule.md`'s
carry table, spec §4 and `TRACEABILITY.md`.

**D6 / B24 — a miscitation that would have read as carelessness.** B24 ("draw the desktop
two-pane work stage") cited **D3**, which is the `rule.md` defect — an unrelated row. The real
evidence was sitting in `prototype.md`'s own "Known gaps". That gap is now **D6** in the spec's
defect table, B24 cites it, and B24 was raised to **Must** to agree with F5 — a gate reviewer
opens the prototype on a desktop, so shipping only the 480 px layout is not a *Should*.

**B34 — new.** NFR4 ("interactive < 2 s") is the one NFR with no agreed measurement basis and no
backlog row. Until a reference device is named in the repo (Q3), the threshold is untestable and
must not be claimed at the gate.

**B22 / B23 / B25 — moved, not renumbered.** These three are gate *process* rows, not product
requirements, and no honest requirement id exists for them. Inventing one to satisfy check 2
would have been the wrong fix. They now sit in their own **Gate deliverables** table citing the
rubric, so the product backlog holds one invariant cleanly: every product row traces to a
requirement id.

### The finding that matters more than any of that

The M1 guide defines a real user in two clauses:

> **(1) they genuinely have the problem**, and **(2) you can reach them to talk.** It doesn't
> have to be face-to-face — a call, chat, DM, or video call all count — and they don't have to
> be on campus.

It names the trap by name: students assume a real user is "someone I can walk up to on campus",
and trap themselves. **Our field kit did exactly that** — four recruitment locations, three of
them physical campus spots. B16 has been sitting at 0 of 5 against a definition far narrower
than the course actually uses.

`field-kit.md` now carries **§1b** — DMs, calls, online communities where people are *already*
posting the pain, and competitor 1–2 star reviewers, who both have the problem and have already
written it down. §7's assignment table gains a remote column per member. `results.md` records
the channel per participant, and LR7 binds unchanged on every channel: a DM is not less
regulated than a corridor.

This does not close B16. It removes the reason it was stuck.

## Third pass — D2 and D4 rebuilt against the deck's notation rules

Reviewed against the W4 deck's own UML slides after the diagrams were read side by side with it.
Both graded diagrams had notation defects.

### D2 — was not a UML use case diagram

Mermaid has **no use-case diagram type**. Drawn as a `flowchart`, D2 rendered actors as rounded
boxes and gave the tool relationships arrowheads — the deck's slide says actors are **stick
figures**, associations are **plain solid lines with no arrowhead**. It also used `«extend»`
six times, which is wrong on the semantics: `«extend»` is *optional, conditional* behaviour, and
compressing a PDF is not an optional addition to transforming a file — **it is a transform**.

D2 is now [`d2-use-case.svg`](../02-design/d2-use-case.svg), hand-authored so the notation is
exact. It is still plain text in the repo and still diffs like code, so nothing became a binary.

| Relationship | Notation | Count |
|---|---|---|
| Association | solid, no arrowhead | 8 |
| Generalization — *is a kind of* | solid, hollow triangle at the general case | 6 tools → 1 core |
| `«include»` — always runs | dashed, open arrowhead | 2 |
| `«extend»` — runs only sometimes | dashed, open arrowhead | 1 |

Generalization is what carries the rubric claim now: *58 tools are 58 settings of one workflow.*
`«extend»` survives in exactly one place — `Delete the result now`, which the student may never
press, because the countdown purges the result either way.

### D4 — a diamond that was neither a decision nor a merge

`merge_run` had **one edge in and one edge out**. That is not a UML node: a decision is 1→2, a
merge is 2→1. It rendered as a diamond nobody had answered, which is exactly how it read. The
retry loop also rejoined the flow at a step that already had an incoming edge, so the diagram
never said where the two paths met.

Rebuilt: the loop now rejoins at `retarget`, a real 2-in merge placed *before* step 3, and both
decisions ask their question on the inbound edge and answer it on both outbound edges.

| Diamond | Kind | In | Out | Guards |
|---|---|---|---|---|
| `under_cap` | decision | 1 | 2 | `[yes]` at or under the cap · `[no]` over the cap, change the target |
| `disposal` | decision | 1 | 2 | `[yes]` student presses Delete now · `[no]` countdown ends, or the tab closes |
| `retarget` | merge | 2 | 1 | — |
| `rejoin` | merge | 2 | 1 | — |

### Fourth pass — D1 and D3 held to the same standard

Having rebuilt the two diagrams that were complained about, the other two were audited against
the deck's own "correct if…" column rather than assumed fine. Both had defects — smaller than

**D1 drew the LMS upload as leaving the device storage.** `Device file storage → MFU LMS` says a

a third-party host. Every external now carries `«actor»` or `«external»`, and the out-of-scope

`ENGINE → vault` render as arrows into a group boundary, which leaves the actual call
ambiguous. The path is now component to component:
`tool-shell → ops → pdf-utils / media-utils / audio-fx → vault`. Four previously unlabelled
arrows were labelled; all 14 now say what crosses them.

Nothing in D3's architecture *claim* changed — no tier was added or removed. What changed is
that the drawing now says what the code does.

## Fifth pass — all four rendered as images and inspected

The first four passes checked the diagrams by *parsing* them. That catches a wrong relationship;
it does not catch a diagram that is simply unreadable. All four were rendered to PNG — headless
Chrome for the Mermaid three, `rsvg-convert` for the SVG — and looked at.

D1, D2 and D4 were fine on sight. **D3 was not**, and none of the earlier checks could have
found it:

| Defect, visible only in the render | Fix |
|---|---|
| The `Browser tab` subgraph title was **clipped by the service-worker box** — the second line ran underneath a node and was unreadable | Title back to one line; the claim it carried moved into a note |
| The "no server tier" note **floated unattached**, stretching the canvas and hanging off the right edge | Anchored to `vault.js` with a dashed UML note line — the component the claim is about |
| The whole diagram was a **1418 × 1656 diagonal staircase** with a large empty quadrant | Recomposed as three labelled layer bands, 1250 × 1550 |
| One box per file — the deck asks for **components, not code** | `main.js + registry.js` and `tool-shell.js + option-ui.js` merged into single components |
| `service-worker` sat **inside `Presentation`**, which it is not | Lifted out to sit directly in the browser-tab boundary |

The last two were introduced and then caught in the same pass: merging the modules compacted the
layout, but the first attempt swept `service-worker` into the presentation layer along with them.
Rendering it again is what showed it.

A left-to-right variant was tried and rejected: it measured 3474 × 851, which scales to
unreadable text in a GitHub markdown column. Aspect ratio is a legibility constraint here, not a
matter of taste.
