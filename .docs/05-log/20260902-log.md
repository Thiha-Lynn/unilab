### The core workflow chosen, and why

**⭐ Transform a file on this device**, instanced as *compress a scanned PDF to the 5 MB LMS
cap*. It is the shortest scenario that exercises F1 (on-device), F3 (named target), F5 (preview
before committing) and F6 (custody) — so one thread runs through all six documents, which is
what the deck says earns the marks.

### design-system.md was extracted, not invented

The deck's method is "hand the agent a spec plus a screen you like". UniLab already ships the
screens, so the tokens were lifted from `src/styles.css` `:root` verbatim — 23 real tokens the
browser renders today. The prototype therefore cannot drift from the app: they read the same
values.

Two of the seven component rules exist for reasons that are not stylistic and are recorded as
such: **R2** (16 px phone inputs — iOS Safari zooms the page under 16 px) and **R7**
(`[hidden]` needs `!important` because it loses to any `display:flex`).

### Rendering defect found and fixed

The first draft of D4 declared two `<<choice>>` states **after** they were referenced in a
transition. Mermaid resolved the forward reference by creating an ordinary state, so the merge
rendered as **a labelled box named "Merge1"** — exactly the "never a labelled Start/End box"
mistake the deck penalises. Caught by rendering all four blocks through Mermaid 10.9.1 and
counting shapes, not by reading the source.

| | Before | After |
|---|---|---|
| Diamonds in D4 | 3 | **4** |
| Stray box labels | `Merge1` | none |
| Blocks parsing | 4/4 | 4/4 |

All four choice states are now declared before use. Verified: `[*]` renders as ● and ◉, guards
are in `[brackets]`, both branches rejoin at a merge before the final node.
