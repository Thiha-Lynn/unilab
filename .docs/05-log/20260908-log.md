## Addendum — D4 guard labels, and what OCR actually ships

### D4: the line was drawn through its own label

Reported from the rendered diagram: the `[no]` edge looked wrong. It was not the arrow — the
**degrees were right all along** — it was the label. Mermaid places an edge label at the midpoint
of its edge and then draws the edge *through* it. `[no] over the cap, change the target` is 35
characters, so the loop-back line came out running between "cap," and "change".

Guards are now `[yes]` and `[no]`, 5 characters, which fit inside their own background box. What
each answer means moved into the table under the diagram, where there is room to read it.

### OCR: the descriptions were wrong in the direction nobody checked

A pass was started to cut OCR to English-only, then reversed on the instruction that the
multilingual support works and should stay. **The reversal was the right call** — and checking
the code to make the change is what turned up the real defect:

```
every description in the repo   Thai, English and Burmese      (3 languages)
ocr-pdf.js LANGS                19 languages, incl. Chinese, Japanese,
                                Korean, Arabic, Russian, Hindi, Vietnamese…
```

Spec defect **D2** was already open on OCR descriptions disagreeing, and B10 "fixed" it on 7 Sep
by making all of them read *Thai, English and Burmese*. That propagated the error rather than
curing it, **because the spec's own description of the code was wrong**. Nobody had opened
`LANGS` and counted.

Corrected everywhere: `registry.js`, `README.md`, spec F8 and D2, backlog B8 and B10,
`TRACEABILITY.md`, `feature-list.md`, the D2 diagram SVG, `rule.md`, and `charter.html`.

`rule.md`'s AI-accountability clause gained the general rule, since it is the clause that governs
this class of mistake: **understating coverage is the same defect as overstating it.** Claiming
three languages while shipping nineteen hid working support from the students most likely to
need it.

> ⚠️ **`charter.html` is the source for the submitted Google Doc.** Its O5 objective and its
> out-of-scope list both named three languages. Both are corrected here, so the Doc needs
> re-pasting before anyone reads the two side by side.

### How the OCR tool actually extracts text

```
1  render     pdf.js draws page n to a canvas at 2x page size (~150 dpi)
2  recognise  Tesseract WASM, PSM.AUTO full layout analysis, optional deskew
              -> plain text + a bounding box per word, in image pixels
3  place      each word is redrawn onto a new PDF at opacity 0, scaled from
              image pixels to PDF points, sized to its own box
4  compose    the original page goes down first as a JPEG; the invisible text
              sits on top, so the page looks like the scan and Ctrl+F works
```

The one real limit is step 3: pdf-lib's standard fonts are WinAnsi, which covers Latin-1 only,
so Thai, Burmese, CJK, Arabic and the rest **cannot go into the hidden layer** — embedding
Unicode fonts for all 19 would add tens of megabytes to the page. Recognition is unaffected;
those languages come out in a `.txt` saved beside the PDF, and the sidebar promises that before
the run rather than surprising the student after it.

## Addendum 2 — D4 rebuilt as a flowchart; cross-diagram alignment verified

### The merge diamonds are gone

Reported from the render: the diamond above step 3 should go, and both arrows — from
`Read the file bytes` and from the `[no]` branch — should enter step 3 directly.

**That is correct UML, and better than what was there.** UML treats *multiple incoming edges on
a node* as an implicit merge, so an explicit merge node is optional. The earlier draft of this
diagram claimed the merge was **required** for the UML to be legal. That claim was wrong and has
been withdrawn.

Dropping it also settles the very first complaint made against this diagram — *"lots of diamond
shapes but no yes/no"*. Bare merge diamonds were exactly that. Now:

> **every diamond in D4 asks a question and has two guarded exits.** One rule, not two.

### Why it moved from `stateDiagram-v2` to `flowchart`

Removing the merges from the state diagram made dagre sprawl it sideways — 794 × 1042 with the
decision floating up beside an unrelated step. Rebuilt as a `flowchart TB`:

| | `stateDiagram-v2` | `flowchart TB` |
|---|---|---|
| Layout after merges removed | 794 × 1042, diagonal | **542 × 1732, straight down** |
| Decision question | on the inbound edge, collided with other edges | **inside the diamond** |
| Guards | had to carry the condition | just `[yes]` / `[no]` |
| ● / ◉ | native | `(( ))` + `(("●"))`, styled |

`(((...)))` was tried for the final node first and does **not** render as a double circle in
Mermaid 11 — it came out identical to the initial node, which would have left a reader unable to
tell the start from the end. A circle containing `●` gives a true UML ◉ using syntax old enough
to be safe on GitHub.
