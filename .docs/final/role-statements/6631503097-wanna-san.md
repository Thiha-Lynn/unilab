## Reflection

### 1. Lessons learned: building UniLab with AI

**What got better:** AI made it easier to move from an idea to something concrete that the team could inspect. It helped with drafting documentation, exploring implementation approaches and creating repeatable checks. For me, the useful lesson was that an AI assistant becomes more effective when it has clear boundaries: the user problem, the requirement, the privacy constraints and the evidence needed to show that a change works. UniLab's rule that file processing stays on the user's device gave those discussions a clear direction.

**What got worse:** AI made it easy to confuse technical possibility with user need. Our repository records that OCR and saved Workflows were built, but the fifteen discovery interviews did not establish demand for them, so their requirements were parked. That is a particularly relevant lesson for an AI Lead: a model-backed feature can be interesting and still be the wrong priority. AI can also repeat an incorrect assumption across several documents. The recorded mismatch between the OCR language descriptions and the actual code shows why consistent wording alone is insufficient. Someone still needs to inspect the implementation and check the evidence.

The interviews credited to me reinforced this point. Students described practical problems with quotas, file order, export quality and moving between tools. A successful solution should reduce those difficulties. Adding a model is useful only when it helps with a real task, works within device limits and explains its limitations clearly.

### 2. Where I stand in the AI-era software industry

I want to develop as a software engineer who can use AI effectively while taking responsibility for the result. Generating code is only part of that work. Understanding a user's problem, choosing an appropriate approach, checking output and explaining trade-offs remain essential skills.

My interest is in practical, privacy-conscious AI integration. For on-device tools, that includes asking whether a model is needed, what happens if it cannot load, how performance varies across devices and how users can check its output. I see my role as connecting AI capabilities with reliable software and clear communication. I want to be able to explain why a feature belongs in a product and what evidence supports its claims.
