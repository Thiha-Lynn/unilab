## 2. Functional requirements

The one core workflow: **select a file → transform it on this device → download the result.**
Each tool is a *parameterisation* of that workflow, not a workflow of its own.

| # | As a… | I want to… | so that… | Priority | Traces to |
|---|---|---|---|---|---|
| **F1** | student | pick a file from this device and get the transformed result back without any upload | my coursework and identity documents stay in my own custody | **Must** | P2 |
| **F2** | student | use every tool without an account, a sign-in, an email, or a task-per-day limit | the tool is available at 11:55 pm on the night it matters | **Must** | P1 |

## 4. Legal requirements

Derived from `rule.md` (W2). The W2 workshop's first instruction was *"pick YOUR product — the
one in your Company Charter, not a case company"*, and the draft written in class did not: it
analysed a generic "upload a file → we host it → we delete it later" service funded by
advertising. The product in the Charter has **no server, no upload, no account, and no ads**.

`rule.md` was rewritten against the Charter's product on **6 Sep 2026** (B12, now closed). The
mismatch was never an embarrassment to hide — it was the finding, and it produced the strongest
compliance answer available to this project:

> **Architecture as compliance: the duties this design removes.**
> A duty you have discharged can fail. A duty you never incurred cannot.

The class draft is preserved verbatim at
[`../04-legal/rule-as-submitted-20260819.md`](../04-legal/rule-as-submitted-20260819.md), so the
graded W2 submission survives the rewrite and the two can be read side by side.

### 4.1 Duties that dissolve — and why that must be written down, not deleted

| Was | Why `rule.md` imposed it | Why it no longer applies |
|---|---|---|
| **CCA §26 access log**, ≥90 days, append-only — declared a *launch blocker* | §3(2) makes anyone **storing data for others** a service provider | We store nothing for anyone. There is no server, no upload, no session, no IP to log. **Not "we chose not to log" — there is no event to log.** |
| **Random file ids, TTL jobs, signed expiring URLs, backup exclusion, cross-tenant checks** (class draft, PDPA rules 1–12) | Duties that begin "the moment a byte arrives" on our server | No byte ever arrives. |
| **Consent banner, ad-script gating, non-personalised ads, partner disclosure, DPA** (class draft, PDPA rules 23–31, ETA rules 1–7) | We planned to fund the product with AdSense | **We do not run ads.** No third party collects anything through the page, so there is no consent to gate. |
| **ETA §9/26 consent records** (who / when / text version / method) | Users would click "I agree" before uploading | Nothing creates an obligation, because nothing is transmitted. |

> **Done — `rule.md` was rewritten on 6 Sep 2026 (B12 closed).** The class draft stated, as
> binding rules, that we are a service provider under CCA §3(2) and a data controller from first
> byte, and named the §26 log a launch blocker. All three are **false of the product we built**,
> so a grader reading that draft and the code together would have found a contradiction. The
> rewrite keeps the required W2 shape — three laws, "what it is / what it requires / rules for
> the agent", direct commands to the AI — applies it to the Charter's product, and closes with a
> **"duties this architecture removes"** table that states each dissolved duty, why it no longer

## 5. Scope

### In scope, this phase
- The one core workflow: select → transform on device → download.
- The 58 shipped tools as parameterisations of it (Image 13 · Video 7 · Audio 11 · PDF 20 · Text 2 · Study 2 · Everyday 3).

- Composable operations (`ops.js` — 13 ops) as the layer Merge and the batch modes run on. The user-facing *saved Workflows* feature is **parked** (F11, §2.1).
