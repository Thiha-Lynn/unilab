## 1. Problem & users

### 1.1 Who

| User | Description | Why they are the target |
|---|---|---|
| **U1 — Undergraduate at MFU** | Coursework in Thai and English; a substantial cohort also works in Burmese. Submits through an LMS with size caps. Phone is the primary camera and often the primary computer. | The product exists for them; the whole team is one. |
| **U2 — Student handling identity documents** | Same person as U1 at a different moment: scanning a transcript, an ID card, a medical certificate for a scholarship, visa, or internship form. | Custody stops being an abstraction here. Drives the whole architecture. |

## 2. Functional requirements

The one core workflow: **select a file → transform it on this device → download the result.**
Each tool is a *parameterisation* of that workflow, not a workflow of its own.

| # | As a… | I want to… | so that… | Priority | Traces to |
|---|---|---|---|---|---|
| **F1** | student | pick a file from this device and get the transformed result back without any upload | my coursework and identity documents stay in my own custody | **Must** | H2 |
| **F2** | student | use every tool without an account, a sign-in, an email, or a task-per-day limit | the tool is available at 11:55 pm on the night it matters | **Must** | H1 |
| **F3** | student | compress an image or a PDF **to a size I name** | I can meet a stated LMS cap on the first try instead of guessing | **Must** | H5 |
| **F4** | student | convert an iPhone HEIC photo to JPG | the upload form stops rejecting my file | **Must** | H4 |
| **F5** | student | see, before I commit, what the tool will do and roughly what it will produce | I don't burn a submission attempt discovering it was wrong | **Must** | H1, H5 |
| **F6** | student | have my finished files disappear from this tab on a visible countdown, with a "delete now" button and an automatic purge when I close the tab | I can *verify* custody rather than trust a deletion promise | **Must** | H2 |
| **F7** | student handling ID documents | redact and blur so the removed content is genuinely gone from the file, not merely covered | a black box over an ID number cannot be lifted off by the recipient | **Must** | H2 |
| **F8** | student | OCR a scanned handout in **the language it is actually written in** — 19 shipped, up to 3 per run — and get a searchable PDF | I can Ctrl+F a 60-page scan and paste a quote instead of retyping it | **Must** | H6 |
| **F9** | student | do video and audio jobs — trim, compress, reframe, clean up a recording — in the same place as my document jobs | I stop keeping four sites bookmarked and relearning each one's limits | **Should** | H7 |
| **F10** | group-work coordinator | merge several PDFs with per-file page ranges and an optional contents page | one report assembles from five members' sections without re-exporting | **Should** | H8 |
| **F11** | student | save a repeated multi-step chore as a named workflow and run a batch of files through it in one go | the weekly chore costs one click instead of five tools | **Should** | H8 |
| **F12** | student | be told, before it starts, when a tool needs to download something from the network, and what it is | the "nothing leaves my device" claim stays honest and I can refuse | **Must** | H2 |
| **F13** | student | install UniLab and keep using it with no connection | a dead campus connection stops being a blocker | **Could** | H3 |
| **F14** | student | see every tool's true language / format coverage in the app itself | I don't skip a tool that would have worked (see D2, §7) | **Should** | H6 |

## 3. Non-functional requirements

Every threshold below is either **measured** (a number from this build, dated) or **proposed**
(a target that needs a decision). Proposed numbers are flagged; per the working agreement they
are **open questions, not settled requirements** — see §7.

| # | Requirement | Threshold | How measured | Basis |
|---|---|---|---|---|
| **NFR1** | No byte of a user's file content leaves the device for any tool except where F12 discloses it. | **0 bytes** of file content in any request body | DevTools Network panel: run each of the 58 tools against a sample file, assert no request carries file bytes | **Partially run, 8 Sep 2026.** *Static, covers all 58:* the 6 `fetch` sites in `src/` are bare GETs for app-owned assets (Noto fonts, rnnoise WASM) — **0** carry a method or body; no `FormData`, XHR, `sendBeacon`, WebSocket or WebRTC anywhere in `src/`. *Dynamic, covers 1 chain:* compress-image → images-to-pdf with all five exit APIs instrumented → **0 attempts** while online. The per-tool sweep across all 58 is still outstanding. → [`02-interviews/h3-measurement.md`](../02-interviews/h3-measurement.md) §2 |
| **NFR2** | Finished files are held in memory only and are unrecoverable after the countdown. | TTL **30 min**; purge on `pagehide`; nothing written to Cache Storage, OPFS, IndexedDB or disk | Code: `src/vault.js` (in-memory `items[]`, `URL.revokeObjectURL`, `pagehide` handler) | **Measured** — implemented as specified |
| **NFR3** | The offline install must be small enough to complete on campus Wi-Fi. | **Proposed ≤ 8 MB** core precache, with anything larger fetched on demand | `du -sh dist`, `precache.json` entry count | **Measured: currently 31 MB across 97 entries — fails.** 23 MB (74%) is one file: `ort-wasm-simd-threaded.jsep.wasm`, the ONNX runtime for Remove Background. See D1, §7 |
| **NFR4** | A tool must reach a usable state quickly on a mid-range student laptop. | **Proposed: interactive < 2 s** on the tool's first paint, excluding the file itself | Manual timing on a reference device | **Proposed — no reference device agreed.** Open question Q3 |
| **NFR5** | Any tool that fetches from the network states what it will download, and roughly how large, **before** the download starts. | 100% of such tools | Inspect each network-using tool's pre-run note | **Measured: 2 of 2 tools disclose (7 Sep 2026).** OCR states engine ~5 MB + 10–15 MB per language in-tool; Remove Background opens at zero bytes and names the model size on the download button itself. → B14 |
| **NFR6** | A long job must not freeze the tab, including when the tab is in the background. | **No main-thread block > 50 ms**; a hidden tab keeps yielding **≥ 1×/second**, not the ~1×/minute Chrome throttles chained `setTimeout(0)` to | Performance panel long-task count over a 60 s job; progress timestamps recorded while the tab is hidden | **Measured** — `audio-fx.js` `breathe()` yields on ~24 ms elapsed and uses `MessageChannel`; a 200 ms job previously froze at 52% in a hidden tab |
| **NFR7** | Text counting must be correct for Thai and Burmese, not only Latin. | **0 miscounts** across a fixture of **≥ 20** Thai / Burmese / emoji strings whose grapheme count differs from a code-point count. Asserts that a base plus its *non-spacing* marks counts as one — **not** that a cluster equals a reader's syllable, since UAX #29 gives a spacing vowel (Thai เ, Burmese ာ) its own cluster | `test/grapheme-counting.test.mjs`, 23 fixtures, each expected value derived from that rule | **Measured** — `Intl.Segmenter` in `word-counter.js`, covered by the fixture test |

> **NFR3 is currently failing and is the clearest measurable defect in the product.** A 31 MB
> install offered to a user whose stated problem (H3) is a slow connection is a contradiction
> the gate will find if we do not.

## 4. Legal requirements

Derived from `rule.md` (W2). The W2 workshop's first instruction was *"pick YOUR product — the
one in your Company Charter, not a case company"*, and the draft written in class did not: it
analysed a generic "upload a file → we host it → we delete it later" service funded by
advertising. The product in the Charter has **no server, no upload, no account, and no ads**.

`rule.md` was rewritten against the Charter's product on **6 Sep 2026** (B12, now closed). The
mismatch was never an embarrassment to hide — it was the finding, and it produced the strongest
compliance answer available to this project:

> **Architecture as compliance: the duties this design removes.**
> A duty you have discharged can fail. A duty you never incurred cannot.

The class draft is preserved verbatim at
[`../04-legal/rule-as-submitted-20260819.md`](../04-legal/rule-as-submitted-20260819.md), so the
graded W2 submission survives the rewrite and the two can be read side by side.

| # | Legal requirement | Statute | Status under the real architecture | Priority |
|---|---|---|---|---|
| **LR1** | The system must not transmit user file content to any server, ours or anyone else's. No upload endpoint exists in the codebase. | PDPA (minimisation; `rule.md` PDPA rules 1–2) | **Satisfied by construction.** No upload path exists. This is the requirement that dissolves the rest. | **Must** |
| **LR2** | The system must not require an account, email, name, or phone number for any tool. | PDPA (`rule.md` PDPA rule 3) | **Satisfied by construction.** No auth code exists. | **Must** |
| **LR3** | Where a tool must reach the network, it must fetch **only** program code or model data — never user content — and must disclose this before the fetch. | PDPA; honesty of the §23 claim | **Satisfied and verified (7 Sep 2026).** Both network-using tools disclose before the fetch: OCR states engine + per-language size in-tool; Remove Background downloads nothing on open and gates the model behind a button that names the size (`remove-background.js` `modelGate()`). → F12, B14 | **Must** |
| **LR4** | No page may claim UniLab "keeps no personal data" or "files never touch a server" **unless the architecture makes both true.** | `rule.md` PDPA rules 23–24 | **Permitted, and conditionally.** The class draft forbade the claim *because that product accepted uploads and ran ads*. This one does neither, so the claim is true and testable — and rule 23 now carries the condition: if an upload path or analytics is ever added, every such claim goes in the **same change**. | **Must** |
| **LR5** | Results must be held in memory only, expire without user action, be erasable on demand, and be unreachable once dropped — proven by test, not asserted. | PDPA (user rights as features; `rule.md` PDPA rules 9–15) | **Satisfied and proven** — `vault.js` TTL + "delete now" + `pagehide` purge, with `test/vault-deletion.test.mjs` resolving the object URL to show the bytes are unreachable rather than flagged. → F6, B26 | **Must** |
| **LR6** | Redaction, blurring and metadata stripping must remove the content, not overlay it — proven by a test that extracts from the output. | PDPA (sensitive data) — `rule.md` PDPA rules 7, 19 | **Partly proven.** EXIF/GPS stripping is enforced and covered (B28); `redact-pdf.js` still **needs the extract-and-assert test.** → F7, B15 | **Must** |
| **LR7** | No interview transcript, name, phone number, student ID, or contact detail may be pasted into an AI tool or committed to the public repo. | `rule.md` PDPA rules 30–32 | **Binds the §6 interview plan from the first interview.** Evidence log stores role, pain, quote only. | **Must** |
| **LR8** | No filename, file content, or object URL may reach the console, an error tracker, or any diagnostic sink in a production build. A message that names the file **on screen** is correct; the same string in the console is not. | `rule.md` PDPA rule 6 | **Satisfied.** `src/log.js` no-ops in production; absence verified in the built bundle. → B30 | **Must** |

### 4.1 Duties that dissolve — and why that must be written down, not deleted

| Was | Why `rule.md` imposed it | Why it no longer applies |
|---|---|---|
| **CCA §26 access log**, ≥90 days, append-only — declared a *launch blocker* | §3(2) makes anyone **storing data for others** a service provider | We store nothing for anyone. There is no server, no upload, no session, no IP to log. **Not "we chose not to log" — there is no event to log.** |
| **Random file ids, TTL jobs, signed expiring URLs, backup exclusion, cross-tenant checks** (class draft, PDPA rules 1–12) | Duties that begin "the moment a byte arrives" on our server | No byte ever arrives. |
| **Consent banner, ad-script gating, non-personalised ads, partner disclosure, DPA** (class draft, PDPA rules 23–31, ETA rules 1–7) | We planned to fund the product with AdSense | **We do not run ads.** No third party collects anything through the page, so there is no consent to gate. |
| **ETA §9/26 consent records** (who / when / text version / method) | Users would click "I agree" before uploading | Nothing creates an obligation, because nothing is transmitted. |

> **Done — `rule.md` was rewritten on 6 Sep 2026 (B12 closed).** The class draft stated, as
> binding rules, that we are a service provider under CCA §3(2) and a data controller from first
> byte, and named the §26 log a launch blocker. All three are **false of the product we built**,
> so a grader reading that draft and the code together would have found a contradiction. The
> rewrite keeps the required W2 shape — three laws, "what it is / what it requires / rules for
> the agent", direct commands to the AI — applies it to the Charter's product, and closes with a
> **"duties this architecture removes"** table that states each dissolved duty, why it no longer
> binds, and the rule that keeps it that way. Nothing was deleted; the §26 rules are now written
> as *"if the system ever stores a file for a user, this duty returns in full"*.

## 5. Scope

### In scope, this phase
- The one core workflow: select → transform on device → download.
- The 58 shipped tools as parameterisations of it (Image 13 · Video 7 · Audio 11 · PDF 20 · Text 2 · Study 2 · Everyday 3).
- In-memory result custody with a visible countdown (`vault.js`).
- Composable operations and saved Workflows (`ops.js` — 13 ops).
- Offline PWA install, **subject to NFR3 being brought into range**.

### Out of scope — explicit Won'ts
| # | Won't | Why |
|---|---|---|
| **W1** | PDF → Word / Excel round-trip conversion | Genuinely needs a server. Doing it would destroy LR1, which is the whole product. |
| **W2** | Accounts, cloud sync, cross-device history | Requires storing user data; contradicts LR2. |
| **W3** | Advertising or any third-party analytics | Would re-impose the entire consent and disclosure regime we just dissolved (§4.1). |
| **W4** | Sending any file content to an AI model or third-party API | `rule.md` PDPA rule 17. On-device only. |
| **W5** | Staff/faculty features, LMS integration | Not our user this phase. |

### The one core workflow this phase builds
> **Select a file → transform it on this device → download the result.**
> Stated this way deliberately: 58 tools are 58 *settings* of one workflow. Described as 58
> workflows, the scope reads as sprawl and fails the rubric.

## 6. How H becomes P — the interview plan (gate-critical)

**Need: ≥5 by 8 Sep 2026 · target ≥15 by month end · currently 0.**

Bound by **LR7**: record **role, pain, quote only**. No names, no student IDs, no contact
details, no recordings retained past transcription. Nothing identifying goes in the repo or into
any AI tool.

**Ask about the hypothesis, never state it.** "Tell me about the last time you had to hand in a

## 7. Open questions — must be answered, not guessed

Per the working agreement, each carries at least three options. **None of these may be decided
by an agent alone.**

**Q1** — NFR3: the 31 MB install. 23 MB is the ONNX runtime for one tool (Remove Background).
1. Drop Remove Background from the precache; fetch the model on first use (as OCR already does). Install drops to ~8 MB; the tool needs one online run.
2. Drop the tool from the offline build entirely; online-only.
3. Keep it and lower the NFR3 target, accepting that offline install is unusable on campus Wi-Fi — which contradicts H3.

**Q2** — Does H9 kill the value proposition? If students already hold free iLovePDF Premium:
1. Lead entirely on custody; drop every "free" claim from the README and landing page.
2. Lead on coverage (video + audio, which they have none of — H7).
3. Lead on offline (subject to Q1).

**Q3** — NFR4 has no reference device. Options: (1) the team's median laptop, specified in the repo; (2) a mid-range Android phone; (3) a throttled desktop profile (4× CPU slowdown) so it is reproducible in CI.

**Q4** — Is UniLab an approved case-study topic? `topic-selection-slide.html` (19 Aug) lists five
assigned topics — Recovery Score, MALA Risk Screening, AI Perfumery Engine, Internship
Management System, Curriculum Revision Tool — and says each team picks one. **UniLab is not on
that list.** Options: (1) confirm with Dr. Prasara that UniLab was accepted as this team's own
topic; (2) map UniLab onto the nearest listed topic; (3) switch topics. **This is a gate-level
risk and must be resolved before 8 Sep, ahead of any further spec work.**
