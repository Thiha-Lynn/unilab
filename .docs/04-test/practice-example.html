One complete worked practice scenario

FICTIONAL TRAINING EXAMPLE — NOT COLLECTED DATA. Every response, outcome and time below is invented to teach recording. No actual participant or consent is represented. Do not copy it into U01–U15, the calculator, the portfolio or a claim of real testing.

Setup

Role-play code: PRACTICE (deliberately incompatible with the real U-code importer). One teammate plays an MFU student outside the course; two others rehearse facilitator/observer roles. Use the same four fictional documents, protocol and local recorder. In a real session, check actual eligibility/age rules, obtain actual consent and record the real build/device/date. Practice verbal agreement is not a real research consent record.

How to interpret it

  • One practice session; zero real participants collected.
  • Within this fictional example, three of four tasks succeed unaided: 75%. An assisted task stays in the denominator.
  • T1 and T2 time reductions are 25%; T4 is 33.3%. Exclude assisted T3 from successful paired timing summaries; show its assistance and time in the overall outcome table.
  • Do not claim study PASS from one example or a good SUS score. Actual cohort size, missingness, TAM, task success, physical-device evidence and defects also matter.

Example defect and retest process

Training defect PRACTICE-D1: password option hard to discover; assign a real owner and severity only after observing an actual issue. For a real defect, record the evidence, fix commit and actual retest result. A retest reuses the same participant code and does not become another user. This example includes no invented fix or retest pass.
